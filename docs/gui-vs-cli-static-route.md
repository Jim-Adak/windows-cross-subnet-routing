# Windows Server 静态路由：图形化界面（RRAS）与 PowerShell

> 文档类型：配置方法补充  
> 验证状态：**PowerShell 方案已在原故障环境验证；RRAS 图形化步骤为操作指南，未在该服务器实际执行。**  
> 关联：[原始故障修复记录](../README.md) · [静态与动态路由分析](static-vs-dynamic-routing.md)

## 1. 能否通过 GUI 添加静态路由？

**可以。** Windows Server 提供“路由和远程访问”（Routing and Remote Access，RRAS）管理控制台，可在 IPv4 的“静态路由”节点添加路由。不过 RRAS 是服务器路由功能的一部分，并非普通网卡 IPv4 属性窗口中的一个简单按钮。仅为单台服务器添加一条路由时，通常优先使用内置 PowerShell 或 `route` 命令。

> ⚠️ **变更风险：** 如果当前服务器已经通过静态路由修复故障，**不需要为了图形界面重新安装或启用 RRAS**。启用或重新配置 RRAS 可能影响网络服务和远程访问。应先在 Hyper-V 测试机中演练，并准备 BMC/控制台等带外恢复手段。

## 2. 本次案例需要的路由参数

| 字段 | 值 |
| --- | --- |
| 服务器地址 | `172.16.76.3/16` |
| 目标网络（Destination） | `172.16.157.0` |
| 子网掩码（Network Mask） | `255.255.255.0` |
| 下一跳（Gateway） | `172.16.76.1` |
| 接口（Interface） | IP 为 `172.16.76.3` 的物理以太网，原环境索引 `16` |
| 跃点数（Metric） | 可按管理要求设置，例如 `1`；不能仅凭数值判断最终选路 |

添加 `172.16.157.0/24` 路由后，它比已有 `172.16.0.0/16` 直连路由更具体，因而对目标地址优先匹配。下一跳必须能够实际转发到目标网段。

## 3. 方法 A：RRAS 图形化配置

### 3.1 安装路由角色服务

在 Windows Server 中打开 **服务器管理器（Server Manager）**：

1. 点击 **管理 → 添加角色和功能**。
2. 选择 **基于角色或基于功能的安装**，选中目标服务器。
3. 在服务器角色中选择 **远程访问（Remote Access）**。
4. 在角色服务中选择 **路由（Routing）**，按向导添加所需依赖并完成安装。
5. 安装完成后，在服务器管理器的 **工具** 菜单中查找 **路由和远程访问**。

> 角色和菜单名称可能随 Windows Server 版本、系统语言和安装方式有所差异。

### 3.2 启用并检查 RRAS

可以通过 **Win + R** 输入：

```text
rrasmgmt.msc
```

打开管理控制台。若服务器尚未配置 RRAS，可在服务器节点右键选择 **配置并启用路由和远程访问**，根据向导及实际网络需求选择适当的自定义/LAN 路由配置。

**不要在现有生产服务器上盲目启用路由转发、NAT 或 VPN 功能。** RRAS 的具体选项取决于操作系统版本和当前角色状态；如果相关菜单不可用，应先检查服务和角色，而不是强行修改。

### 3.3 新建 IPv4 静态路由

在 RRAS 管理控制台中：

1. 展开服务器节点及 **IPv4**。
2. 找到 **静态路由（Static Routes）** 节点。
3. 右键选择 **新建静态路由（New Static Route）**。
4. 选择连接到 `172.16.76.3` 的物理以太网接口。
5. 输入目标 `172.16.157.0`、掩码 `255.255.255.0`、网关 `172.16.76.1`，按需设置跃点数。
6. 确认并查看静态路由列表和系统路由表。

GUI 中的路由配置由 RRAS 管理；其保存和生效行为不应与 `New-NetRoute -PolicyStore ActiveStore` 完全等同。请在测试机验证重启后的状态。

## 4. 方法 B：PowerShell（本次实际验证的方案）

管理员 PowerShell：

```powershell
New-NetRoute `
  -DestinationPrefix "172.16.157.0/24" `
  -InterfaceIndex 16 `
  -NextHop "172.16.76.1" `
  -PolicyStore ActiveStore
```

这是原案例已验证成功的临时路由方案。确认后再考虑持久化：

```powershell
New-NetRoute `
  -DestinationPrefix "172.16.157.0/24" `
  -InterfaceIndex 16 `
  -NextHop "172.16.76.1" `
  -PolicyStore PersistentStore
```

也可选择传统 `route -p add` 命令进行持久化，**不必重复采用多种持久化方法**。创建前先检查是否已有同一目标路由，避免重复项。

## 5. 图形界面中容易混淆的设置

打开 `ncpa.cpl` → 网卡属性 → IPv4 → 高级，通常可以配置 IP 地址、默认网关和接口相关选项，但**并没有一个通用的“任意目标网络静态路由”编辑入口**。

**默认网关 ≠ 指向特定网段的静态路由。** 在本例中，即使服务器已经有 `0.0.0.0/0 → 172.16.76.1`，目标仍会优先匹配 `172.16.0.0/16`，因此仅重新填写默认网关不能解决该选路问题。

## 6. 验证与回滚

添加路由后，在 Windows Server 上执行：

```powershell
Find-NetRoute -RemoteIPAddress 172.16.157.222
Get-NetRoute -DestinationPrefix "172.16.157.0/24"
route print -4
```

检查实际选路是否为 `172.16.157.0/24`、下一跳是否为 `172.16.76.1`、接口是否正确。随后从 Windows 11 分别测试 Ping、`Test-NetConnection 172.16.76.3 -Port 3389` 和实际 RDP 连接。Ping 不通并不必然意味着 TCP 不通。

撤销使用 PowerShell 添加的**临时**路由：

```powershell
Remove-NetRoute `
  -DestinationPrefix "172.16.157.0/24" `
  -InterfaceIndex 16 `
  -NextHop "172.16.76.1" `
  -PolicyStore ActiveStore `
  -Confirm:$false
```

若还添加了 PersistentStore 持久路由，应单独核实并删除对应持久配置。对于 **RRAS GUI 添加的路由**，优先通过 RRAS 的“静态路由”列表删除并检查系统路由表，不要假定其管理状态与 NetTCPIP 的路由存储完全一致。

## 7. 如何选择？

| 维度 | RRAS 图形界面 | PowerShell |
| --- | --- | --- |
| 额外角色 | 通常需要安装、配置路由服务 | 不需要 |
| 适用场景 | 已部署 RRAS 的路由服务器、图形化管理 | 单台主机修复、脚本自动化 |
| 配置风险 | 启用服务可能影响服务器网络行为 | 可先仅添加临时路由 |
| 本案例 | **仅作为备选操作指南** | **已验证成功，推荐** |

## 8. 总结

Windows Server 确实能够通过 **RRAS 图形界面**添加 IPv4 静态路由，但对本次单条 `172.16.157.0/24` 路由的需求，**PowerShell 更直接、变更范围更小**。GUI 方案不代表已在原服务器上测试过；后续如在 Hyper-V 中完成 RRAS 实验，可以再补充实测截图、系统版本和重启后的验证结果。
